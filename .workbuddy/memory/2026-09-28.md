## P1 完成：SQLite 索引库 + 稳定 uid + relations 预留

`app/tools/build_index_db.py` → `data/index/index.db`（产物，可删重建）：
八张表 + FTS5。实测：sentences 96,336 / mentions 66,209 / persons 2,240 /
aliases 6,040 / places 1,575 / relations 0（预留）。与 book-data.json 逐项核对一致。

三件做对的事：
1. **mentions 独立成表**——原本埋在 `sentence.marks` 嵌套数组里没法查，
   现在能直接筛 `tier='guess'`（1,146 处），这是「方便查找确认」的入口。
2. **sentences.uid 稳定主键**，且**优先复用库里已有的**（重跑 96,336 条全复用、0 新建）。
   ⚠️ 已知限制写在 `make_uid()` 注释里：目前按 (篇,段序,句序) 匹配，
   P4 真正支持编辑句子时要改成按文本内容匹配。
3. **relations 表先建后填**（关系图/族谱的接口，成本≈0，漏了要重扫全语料）。

**⚠️ 最大的坑：FTS5 对中文默认分词**。unicode61 把连续汉字当成一个 token，
整句就是一个 token → 搜「項羽」只命中 **2 句**（实际 922 处）。
解法：**按字切分入库**（每字一 token）+ 查询时同样按字切分并用**短语查询**
`MATCH '"項 羽"'`。改后命中 413 句。
不用 `tokenize='trigram'`：它要求查询词≥3 字，而中文人名多为 2 字。

**另一个坑**：mentions/aliases 是追加写入，重跑会翻倍。
改成「先偷出旧 uid → 删库 → 重建 → 复用」，`--fresh` 可强制全部重分配。

配套查询工具 `app/tools/query.py`（替代一次性 `_probe_*` 脚本）：
```
python app/tools/query.py --stats        库规模 + tier 分布
python app/tools/query.py 梁王            自动识别同名异人（劉永/劉暢）
python app/tools/query.py --fts 鴻門
python app/tools/query.py --tier guess -n 30
```

数据流是**单向**的：`xlsx（权威）→ build_dict → book-data.json → index.db`。
任何环节都不回写 xlsx（红线 1）。DEV.md 里原本写的「xlsx ↔ SQLite 双向」
措辞有误，已改为单向。

回归：6/6 全绿，49 秒。
