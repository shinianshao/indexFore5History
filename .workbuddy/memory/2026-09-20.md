## 本地版落地：管线跑通 + 网页工具可用（同日）

用户提出「不做小程序，先在自己电脑上玩」，采纳。关键原则：本地版与小程序版**共用同一套数据管线**，将来上小程序只换展示层，管线零改动。

**网络验证**：维基文库可直连（站点 + API 均 200）✓；ctext.org 返回 403（有反爬）；古诗文网可访问。语料源定为维基文库。

**已建成管线（`pipeline/`）**：
| 脚本 | 职责 |
|---|---|
| `check_sources.py` | 语料源连通性检测 |
| `fetch.py` | 抓取 `史記/卷001`~`卷130`（已抓 10 卷） |
| `fetch_meta.py` | 从主页目录提取「卷号→篇名」 |
| `build.py` | 提取正文 + 切分（篇→段→句），产物 `data/corpus/sj-00N.json` |
| `annotate.py` | 别名标注 + 建索引，产物 `data/index/book-data.json`、`web/app-data.js` |

**数据事实（史记卷001–010）**：10 篇 / 4643 句 / 80161 字 / 25 个人物，1077 句命中实体。刘邦 327 处（跨 5 篇）、项羽 260 处（3 篇）。

**踩坑记录（重要，避免重犯）**：
1. 维基文库正文是**繁体**（`項羽本紀`、`高祖本紀`），体例判断必须同时匹配简繁——`"本紀" != "本纪"`。
2. 页面头部有导航与提示模板，必须剔除（`三家註版`、`参阅维基百科中的：刘邦` 等），否则「刘邦」会误命中模板文字——这恰是"搜不到正确结果"的反面教材。
3. 篇名不在 `<a>` 标签文本里，而在 `</a>` **之后**的文本中，需再去掉末尾序号（第一/第二）。
4. 别名匹配必须**按长度降序占位**，否则「漢高祖」会被「高祖」截断。
5. 单字别名（禹/尧/舜/纣）保留；易混单字（季/籍/政/信/何）一律排除，避免误命中。

**交付**：`web/` 本地网页工具（index.html + app.js + app-data.js），双击 index.html 即可用。检索「刘邦」按「整篇讲述」与「其他篇目提及」两组展示，高亮原文中**真实出现的别名**（沛公/高祖/漢王/劉季），而非查询词本身。本地预览端口 8765。

## 规模化：词典 25→257 人 + 史记 130 卷全量（同日）

**抓取**：`fetch.py` 重写为**抗限流版**——请求间隔 2.5s、429/5xx 指数退避（15/30/60/90/120s）、全量跑完自动对失败卷补抓一轮、已有文件跳过（重复执行＝补抓缺失）。首轮 98 ok / 22 fail（20 卷 429 限流 + 1 卷沙箱拒写 + 1 卷 502），补抓后 **130/130 全部到位、0 失败**。

**词典**：新增 `pipeline/build_dict.py` 作为**词典唯一来源**（PERSONS + CHAPTER_OWNERS 两张表），用 OpenCC 自动由繁体别名推导简体，避免手写两套写法出错。产物 `data/dict/people.json`：**257 人物 / 845 别名 / 110 篇有主人公**（十表与八书无主人公、116/128 为民族与占卜专论）。篇目主人公按纪传体例由篇名指定，显式列表而非命名推断，保证可复核。

**四个关键技术决策（都有实证支撑，务必保留）**：

1. **异体字归一**（`annotate.py` 的 `VARIANTS` 表，1 换 1 因此不破坏高亮下标）。维基文库正文混用异体字：`髙`167、`閒`387、`歳`278、`彊`574、`説`117、`戸`30、`鄕`24、`巻`7 次。实证：`河間獻王` **0 命中** / `河閒獻王` **12 命中**——不做归一，整个「刘德」查不到。归一后 257 人**零漏配**。
2. **限定篇目的单字指代**（`build_dict.py` 的 `SCOPED_ALIASES` + `annotate.py` 分篇目小正则）。有的人物正文里只以单字出现（《太史公自序》「喜生談，談為太史公」；《三王世家》通篇以「閎」「旦」「胥」相称；《項羽本紀》「有美人名虞」）。全局收录单字会误伤「旦日」「不虞」「胥靡」，故限定篇目内匹配。解决 5 个原本零命中的人物。
3. **正则总匹配**替代逐别名 `find`：845 条别名编译成单个正则（长度降序），一次扫描，比逐条查找快一个数量级；正则会话消费已匹配文本，天然不重叠。
4. **三家注必须剥离**：维基文库把「集解/索隱/正義」夹注写在 `〈…〉` 内，不清掉则卷027《天官書》从正经文约 5 千字膨胀到 **34905 字**，页面展示的"原句"会是注释。剥离 `〈…〉` + 丢弃含 `【】`、`|` 链式导航、纯标题行（`曆書第四`）与 `作者：`/`史記巻` 等模板行后，卷027 降至 **8859 字**，全库残留噪声段落 **0**。

**十表内容提取**（`build.py` 改造）：十表在维基文库整篇是 `<table>`，旧逻辑一律剔除表格会使卷013-022 近乎空篇。新逻辑按 class 区分——剔除 `ws-header`/`ws-footer`/`ws-noexport`（导航与版权），保留 `wikitable`/`dynlayout-exempt`（正文表），单元格内容按段抽取（单元格最小长度 2 字、散文段最小 4 字，都要求含汉字，否则 `←`、`元` 这类符号会混入）。卷018《高祖功臣侯者年表》因此拿到 16645 字 / 940 个表格段（含「夏侯嬰」「王吸」等功臣名与侯功事迹）。

**最终数据规模**：130 篇 / 46527 句 / **693426 字** / 257 人物 / 845 别名 / **9588 句命中实体**。产物尺寸：`book-data.json` 2.4MB、`corpus-data.js` 2.1MB（本地 file:// 直开无压力）。

**前端升级**（`web/`）：新增**全篇阅读浮层**——点击篇名打开正文、点击原句定位到该段（回填 `data-para` 高亮）；正文中按当前人物的全部别名高亮（长别名优先、不重叠）。因「表」类篇目段落可达数千（十二諸侯年表 3267 段），阅读器**分批渲染**（每批 500 段 + 「显示余下 N 段」）。另加「人物索引」（全部 257 人按提及次数排序，可点击直查）与「篇目一览」（按本纪/世家/列传/表/书分组，标注主人公）。
