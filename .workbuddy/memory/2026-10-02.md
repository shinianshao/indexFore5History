### 这次真正抓到的两个 bug（都在 app.js 的 hash 路由上，是长期潜伏的）

1. **`lastWritten` 守卫从来没生效过**：`location.hash` 会把中文百分号编码，
   `h === lastWritten` 永远不等 → 每次中文检索都二次渲染，把用户刚点的标签页顶回去。
2. **路由正则 `([^?]+)` 贪婪**：`#/q/舜操/person` 里把 `/person` 一起吞进查询词 →
   下一轮写出 `舜操/person/person` → **每点一次长一段** → 超 64 字变 422。
   坑二一直被坑一遮着（守卫失效 ⇒ 根本走不到解析那行），修好坑一才暴露。
3. **`writeHash` 提前 return 时没更新 `lastWritten`** → 上一次写入的 hashchange
   到达时拿旧值对不上，被当成外部跳转。
修法统一成 `normHash()`（解码 + %2F 还原），守卫与解析**吃同一份**，正则收紧成 `[^?#/]+`。

> ⚠️ **教训：两个地方共用一个「规范化后的值」时必须都改。**
> 只改一处，会把另一个坑从遮蔽下放出来——而且新暴露的那个看起来像「我刚改坏了」。

## 补：hash 修复的第二层（比第一层更值得记）

修掉「守衛失效」之后，索引 UI 测试反而红了 1 条：`/api/search?q=舜操/person/person/…` 422。
原因：路由正則 `([^?]+)` 貪婪，把 `#/q/舜操/person` 的 `/person` 一起吞進查詢詞，

**教訓：兩個地方共用一個「規範化後的值」時必須都改，只改一處會把另一個坑從遮蔽下放出來。**

## 原文层跳段 + 只看相关段落（docs/30 §五 第 3 项）

纯前端，1h → 实测约 1.5h（数据形状改动比预估多）。对齐静态版的两个能力：
- **跳段**：段号输入 + `/ 总段数`，回车也行，越界有提示（不静默无反应）
- **只看相关段落**：只留与当前人物有关的段，长篇救命功能

### 两个设计决定
1. **短篇（<40 段）不显示跳段控件**——加了是噪声。
2. **命中信息不从 `/api/chapter` 拿**：那会让 564 篇每篇都带全部 marks，payload 翻十几倍。
   人物页渲染时已拿到 `mentions`（带 uid），存进 `readerState.hitUids`，开筛选时才反查段落。
   ⚠️ **`mentions` 有 `limit`（默认 200）**，所以筛选是「本页已加载的命中」不是全集——
   人物页本身也只显示前 N，**两者口径一致**，不会出现「原文层说没有、人物页说有」。

### 踩的坑
1. **离线快照的 `sents` 存的是 `[uid, 篇号, 正文]`，没有段号** → 跳段在离线版整个失效。
   段界≠句界，前端**推不出来**，而离线版没 db 可查 → 只能存。
   改成 4 位 `[uid, 篇号, 正文, para_seq]`（+0.3MB）。
   ⚠️ **export 里有三处 `enumerate(sents)` 要同步改**（`_chapters` / `uid2i` / 说明文字），
   漏了两处 → `ValueError` 在导出中途炸，**dist/ 留着上一次的旧档（还能打开，更难发现）**。
   → 已加断言 `export_static --verify` 守形状：4 位 / 段号齊全 / 篇內單調遞增。
   **「改数据形状必配断言」，这条已经第二次因为形状变更踩坑。**
2. **段落过滤不能打斷續接標記的引號計數**：先掃全量算 `open`，再決定渲染哪些，
   否則後面全是「未收口」，`q-cont`/`q-open` 全錯。
3. **UI 測試寫了三處錯**（症狀都是「等不到」而不是報錯，最難查）：
   - `out.querySelectorAll("#readerBody p")` —— 原文層在 `#readerBody`，**不在 `#out` 裡**
   - `out.querySelector("#readerBody p.target")` —— 同上
   - 人物索引條目是 **`.item[data-name]`**，`.row[data-pid]` 是**搜索結果行**；
     完整路徑 = 人物索引 → 點人名填檢索框 → 出 `.row[data-pid]` → 點進人物頁
   - 跳段必須在**長篇**上測（短篇控件本來就隱藏，測了等於沒測）→ 從 `D.chaps` 裡找段數多的
4. `app.js` 裡 `offChapter` 是**私有函數**，測試拿不到 → 直接讀 `window.BOOKINDEX_DATA`。
