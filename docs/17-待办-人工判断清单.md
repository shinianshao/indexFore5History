# 待办 · 人工判断清单（模板 + 流程 + 台账）

> 口径（2026 用户）：守卫做不到 100% 正确——**先尽力改善到最后**；
> 仍不能判断的形成**人工清单**等反馈；难以判断的先设 **「未知」**。
> 关联 skill：`person-alias-coverage` §铁律 7 · `title-era-guards` §〇。

---

## 〇、为什么换成这个格式

旧版清单长这样：

```text
| 1 | 高祖 | js×31 兜刘邦 | 刘邦 | 刘邦、刘渊、石勒、刘备、司马懿 |  |
```

**判不了**——只有统计数字，没有原文、没有篇目、没有候选人的朝代。
（2026-09-25 用户反馈：写得再全我也没法勾。）

现在定死：**一条待判条目必须自带三项证据**，缺一项不算条目：

| 证据 | 回答什么 |
|------|----------|
| **归属分布 + tier 构成** | 现在归给了谁、靠什么依据归的（guess 越多越可疑） |
| **原文上下文**（【】标出命中串，前后各 14 字） | 这句话到底在说谁 |
| **候选人的朝代** | 谁的时代对得上（判「高祖 = 刘邦还是司马懿」就靠这个） |

条目一律由 `pipeline/_gen_review_items.py` **生成**，不手敲。

## 一、原则（三层，不变）

| 层级 | 动作 |
|------|------|
| 能修 | 长名 core / `ALIAS_STOP_*` / `GENERIC_BOOK_CANDIDATES` / 扩 books |
| 仍歧义 | 进 **人工判断清单**（`docs/17-条目-*.md`），用户勾选后回填 |
| 难判断 | **未知**：`none` 不标，或 `guess` + UI「歸屬存疑」；禁伪称 era |

已定为「未知 / 不硬归」的策略：

- 泛称 `default` 早于本篇且无同代接近候选、又非合理追述 → `none` 或 `guess`，**不记 era**。
- 分书候选收束后仍多人 → 保持多候选，靠 owner/related/sentence；全无信号则 `guess`/`none`。
- 守卫表宁缺勿滥：不确定的邻字**不要**写入 `ALIAS_STOP_*`（防误杀真阳性）。
- 已清掉的假人名（官职残片/郡名/数量词/言於帝等）**不再入典**。

## 二、条目模板（空白，生成器即按此产出）

```markdown
## 「<称号>」

- **当前 default**：<pid> <名>（<朝代>）
- **候选（GENERIC）**：<pid1> <名>（<朝代>）、<pid2> <名>（<朝代>）

### @<书> · <N> 处 / <M> 篇

**归属分布**

| 当前归属 | 处 | tier 构成 |
|---|---:|---|
| <pid> <名>（<朝代>） | 31 | owner4 / chapter12 / guess23 |

**原文上下文**（【】为命中串，前后各 14 字）

| # | 篇目 | 原文 | 当前归属·tier | 你的判定 |
|---|---|---|---|---|
| 1 | 晉書·宣帝紀 | 尊號曰宣皇帝，陵曰高原，廟稱【高祖】。 | 司馬懿·owner | 对 |

**你的判定**（A / B **二选一**，不要同时用）

**A. 逐条判（默认，推荐）**——直接在上面表格的「你的判定」列写：

| 你写的 | 含义 |
|---|---|
| `对` / 留空 | `对`＝认可当前归属；**留空＝这条没判**，执行方跳过，不猜 |
| `司马懿` | 归这个人（写人名或 pid 都行，繁简不限） |
| `未知` | 判不了，改 `none` 或保留 `guess` + UI「歸屬存疑」，**不硬归** |
| `不标` | 确认这串不是人名，整串出索引 |

> 逐条判定的落地方向：能提炼出**邻域关键词**的（年号、谥号、典故人物、套语）
> → 写进 `GENERIC_CONTEXT_RULES`（⓪ 级硬证据）；提炼不出来的就单留着，
> 别为了填满而硬改 `default`——动 default 会误伤真追述。

**B. 整体兜底**（只在"这批几乎都该归同一个人"时用，勾一个）

- [ ] 归 `____`（写 pid 或人名）
- [ ] 按书分：`<书>`=____、其他书=____（走 `GENERIC_BOOK_CANDIDATES`）
- [ ] **未知**：不硬归，改 `none` 或保留 `guess` + UI「歸屬存疑」
- [ ] **不标**：整串出索引（确认不是人名）

**回填动作**（执行方填）

- 改哪个字段：`GENERIC_MANUAL` / `GENERIC_DEFAULT` / `GENERIC_BOOK_CANDIDATES` / 某人 `core`
- 加哪条断言：`verify.py`
```

### 怎么读一行证据

| 字段 | 含义 |
|------|------|
| `owner` | 本篇篇主，**最可靠**（帝纪里「高祖」= 本篇皇帝） |
| `related` / `sentence` / `paragraph` | 上下文里有强信号（同句/同段出现该人） |
| `chapter` | 全篇只有这一个候选（弱，但一般对） |
| `era` | 按断代史时代窗择近（需核对 `ERA_ORDER`） |
| `guess` | **硬兜 default，最可疑**——优先看这些 |
| 「被更长的别名接管」 | 如「漢高祖」由长名命中，长名优先属**正确行为**，不用处理 |
| 「真漏标」 | 正文有该串却无任何标注——**这是 bug，不是噪声** |

## 三、流程（四步，以后都这么办）

**1. 挑哪些该人判**

```bash
python pipeline/_gen_review_items.py --list
```

按 `guess` 处数降序排——`guess` = 算法硬兜 default，是最可能张冠李戴的地方。

**2. 生成条目**（一个批次一个文件，命名 `docs/17-条目-<批次>.md`）

```bash
python pipeline/_gen_review_items.py --alias 高祖 --alias 武帝 --book js \
    --per 6 --out "docs/17-条目-晋书帝号.md"
```

- `--per N`：每书取几条上下文（默认 6；难判的给 10）
- 脚本只读数据，只写 `--out` 指定的文件；文件头会记下**可复现的生成命令与日期**
- 上下文按 pid **轮转取样**，证据不会全落在第一人身上

**3. 判定**：在「你的判定」列写 pid/人名，或勾底部四个选项之一。
判不了就勾**未知**——不要为了填完而硬归。

**4. 回填**（执行方）：

```bash
python pipeline/build_dict.py && python pipeline/annotate.py \
    && python pipeline/annotate_pei.py && python pipeline/annotate_js_note.py
python pipeline/verify.py --check     # 基线只许升不许降
```

- 每条结论 → `verify.py` **加一条断言**
- 结论抄进本文 §五 台账 → 批次文件可删（数据变了可重跑再生）
