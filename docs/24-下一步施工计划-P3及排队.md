### P3-1 · 一键重建（先把"改完要敲五条命令"消掉）

| 项 | 内容 |
|---|---|
| 新增 | `app/tools/rebuild.py`（或 `scripts/rebuild.sh`） |

> 这一步几乎零设计，纯搬运，但价值极高：**它把"改表"从五步变成一步**，
> 后面所有"编完看变化"的体验都建在它上面。

### P3-2 · 快照库 + diff（Q1=B：落 SQLite，可翻历史）

**为什么是独立的快照库，不是主库里的表**：`index.db` 的定位是**可删重建的产物**
（`build_index_db.py` 是「偷旧 uid → 删库 → 重建」），把不可再生的历史快照放进去
会被重建冲掉。所以快照放 `data/index/snapshots.db`，比较时用 SQLite `ATTACH` 跨库查，
`index.db` 仍可随时删重建，两不相扰。

```sql
-- snapshots.db
CREATE TABLE snapshots (            -- 一次快照
  id INTEGER PRIMARY KEY, created_at TEXT, label TEXT,
  n_sentences INTEGER, n_mentions INTEGER, note TEXT);

CREATE TABLE snapshot_mentions (    -- 该次快照的每条命中
  snapshot_id INTEGER, uid TEXT, s INTEGER, e INTEGER,
  surface TEXT, pid TEXT, tier TEXT);
CREATE INDEX ix_sm_key ON snapshot_mentions(snapshot_id, uid, s, e, surface);
CREATE INDEX ix_sm_pid ON snapshot_mentions(snapshot_id, pid);

CREATE TABLE diffs (                -- 一次比较的汇总
  id INTEGER PRIMARY KEY, created_at TEXT, base_id INTEGER, new_id INTEGER,
  n_added INTEGER, n_removed INTEGER, n_pid_changed INTEGER, n_tier_changed INTEGER,
  note TEXT);

CREATE TABLE diff_items (           -- 明细，每条自带上下文
  diff_id INTEGER, kind TEXT,       -- added/removed/pid_changed/tier_changed
  uid TEXT, s INTEGER, e INTEGER, surface TEXT,
  old_pid TEXT, new_pid TEXT, old_tier TEXT, new_tier TEXT,
  chapter_id TEXT, context TEXT);
```

| 设计点 | 决定 |
|---|---|
| **比较键** | `uid + s + e + surface`（四元组唯一确定"这一处命中"） |
| **变化分四类** | 新增 / **消失（最该看的一类）** / 改归（同键不同 pid）/ **tier 变化**（归属没变但置信度变了，改词典常只动这个，值得单列） |
| **快照取样时机** | **重建第一步、build_dict 之前**取当前库（旧状态）。这样 diff 才能含 override 的效果（override 在 build_index_db 前应用） |
| **容量与保留** | 一次快照 = 命中数那么多行；保留最近 N 次（默认 20，`--keep`）。`diff_items` 设上限（默认 2 万），超出只存汇总并在 `note` 写明截断 |
| **输出** | 终端照样打印 Top N（零成本）+ 落表供翻历史 |

```bash
python app/tools/rebuild.py                  # 一键重建：自动 dump 快照 + 自动 diff
python app/tools/diff.py                     # 最近两次快照重算
python app/tools/diff.py --base 3 --new 5    # 指定两次比
python app/tools/diff.py --kind removed --top 30
```

验收：改一个别名 → 重建 → diff 报出预期的新增/消失，数量与改动相称；
连续两次重建（中间不改表）四类计数**全为 0**。

### P3-3 · `overrides.xlsx` + 应用器（Q2=A）

**列定义**（区分"谁写"，这是本步最容易出错的地方）：

| 列 | 谁写 | 说明 |
|---|---|---|
| `uid` / `s` / `e` / `surface` | 录入时 | 定位一条命中 |
| `nth` | 录入时 | 该句内第几个同名命中——**冗余锚**：`s/e` 在 P4 开放改句子边界后会失效，届时靠它兜 |
| `chapter` / `context` | 录入时 | 篇目 + 前后各 14 字（与 docs/17 条目格式一致，判断必须自带上下文） |
| `old_pid` / `old_tier` | 录入时 | 原归属快照 |
| **`new_pid`** | **人写** | 应归给谁（写人名或 pid 都收） |
| **`action`** | **人写** | `reassign` 改归 / `drop` 确认不是人名整串出索引 / `keep` 认可现状（留档） |
| `status` / `note` / `created_at` | 人写 / 录入时 | `active` / `dead`；备注 |

> ⚠️ **这里会重演 P0 那次事故，先立规矩**：`old_*` / `context` 这些"脚本会填的列"，
> **只能在录入那一刻写，重建时绝不刷新**——否则就等于 `build_workbook.py` 冲掉权威源重来一遍。
> 判据一句话：**pipeline 对 `overrides.xlsx` 只有读权限**；写由 UI / 录入脚本承担，
> 写不进去（Excel 打开着）就写 `.new.xlsx` + 报差异。

**应用方式与时机**：新增 `app/tools/apply_overrides.py`，读表 → 改 `book-data.json` 的
`marks`，执行位置在 annotate 四步**之后**、build_index_db **之前**。
**不动 annotate 引擎**（符合"三层算法不推倒"）。`drop` → 该命中不进库；
`reassign` → 改 pid，`tier` 记 `override`（前端按 docs/21 §12.3 的规则呈现）。

验收：写一条 override → 重建 → `query.py` 查该句归属已改；且这条变化出现在 diff 的
`pid_changed` 里。

### P3-5 · 断言（收尾）

| 断言 | 内容 |
|---|---|
| override 生效 | 写了 `reassign` 的命中，归属必须等于 `new_pid` |
| `drop` 生效 | 被标 `drop` 的命中不出现在库里 |
| 空跑 diff 为 0 | 连续两次重建（中间不改表）四类计数全为 0 |
| 快照递增 | 每次 rebuild 后 `snapshots` 表 +1 行，且 `--keep` 之外的旧快照被清 |
| 单向性 | rebuild 前后 `overrides.xlsx` 的 md5 **必须不变**（防回写，直接断言红线 1） |

### 三个坑（都是"跑起来静悄悄出错"那一类）

1. **两份快照互比恒为 0**。快照都是在重建**前**取的，`diff_last()` 比较最近两份
   → 两边都是旧状态，改了什么也报不出来。
   **diff 的「新」侧必须是重建后的当前库**（`_load_live()`），不是另一份快照。
2. **复原只跑 `annotate.py` 会丢 `places`**。地名是 `annotate_places.py` 加的，
   少了它 `book-data.json` 缺键，旧断言 `verify.py` 直接 `KeyError: 'places'`。
   凡"重标注"一律走 `rebuild.py`（四步连跑）——这条铁律在新链路同样成立。
3. **subprocess 参数不能写成一个字符串**：`run("overrides.py apply")` 会被当成
   含空格的文件路径，python 找不到文件、退出码非 0，但**看起来像"脚本失败了"**。
   参数必须分开传。

顺带一条断言写法：drop 的验证要**数条数**（一句常有同名多命中），
不能查"还找不找得到"——移掉一条后仍找得到，会误判成 drop 没生效。

### 与计划的四处偏差（都是实现时改的，记下来免得对不上）

- `reassign` **不改 tier**，而是保留原 tier 并加 `override: 1` 字段——
  不引入前端不认识的 tier 值。
- `diffs.new_id` 为 NULL（新侧是当前库，不再单独存一份快照），
  因此历史 diff **不能重算**，只能翻 `diff_items` 明细。
- 快照默认保留 **5 份**（不是 20）：每份与命中数等行，20 份会到 200MB。
- 多了 `snapshot.py drop --id`：清自检留下的脏快照。
