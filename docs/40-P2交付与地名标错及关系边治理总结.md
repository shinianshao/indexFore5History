## 二、架构与关键技术决策

### 1. 地名标注 `pmarks` 与 `marks` 的异构同流处理
- **数据结构**：在语料中间件 `book-data.json` 中，句级人物标注为 `s["marks"]`，地名标注为 `s["pmarks"]`，二者格式完全对称（`{s, e, pid, tier, alias}`）。
- **`overrides.py cmd_apply` 增强**：
  - 通过 `orig_pid.startswith("pl_")` 或 `new_pid.startswith("pl_")` 分支优先在 `pmarks` 中匹配候选；
  - 若命中在 `pmarks` 但改归为人名（`new_pid` 非 `pl_`），自动从 `pmarks` 迁入 `marks`；反之亦然；
  - 保证在 `rebuild.py` 执行 `build_index_db.py` 时，`place_mentions` 表能直接准确感知所有地名纠错。

### 2. 前端同构与作用域防污染
- **`app/web/app.js` 同步治理**：
  - `renderPlace` 与 `renderPerson` 严格对齐：并发加载 `loadOverrides()`，维护 `ovMap`，输出 `data-s`、`data-e`、`data-surface` 与 `data-pid`；
  - 明确切换页面时作用域互斥：`renderPerson` 显式置 `currentPlace = null`，`renderPlace` 显式置 `currentPid = null`；
  - 纠错后刷新逻辑自动判断当前视图（`currentPlace ? renderPlace(currentPlace) : renderPerson(currentPid)`），彻底消除视图错位。

### 3. 关系边去重与元数据推导契约
- **去重判据**：严格使用 `(person_a, person_b, rel)` 业务三元组及反向边映射，杜绝仅靠 `rel_id` 去重带来的漏洞；
- **推导来源**：
  - 有证据边（31 条）：其 `book` 由 `evidence_uid` 所在句子之 `chapters.book_id` 100% 逆向推导，不臆造；
  - 无证据边（68 条）：若两端人物在五书中仅重合于唯一书号，则填入该书；跨多书者留空，保证按书检索时不会被误杀。
