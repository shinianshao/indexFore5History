## ⚠️ 断言铁律
- 每修一个坑加一条断言，基线**只许升不许降**；改完必须「**注入错误 → 变红 → 还原 → 变绿**」。
- **红线断言要断在「会被打破的那一层」**；端点层**必须真打一次 HTTP**。
- ⚠️ **恒真断言是这类坏里最贵的**，已踩七种：① `all()` 对空列表返 True；② 宽松选择器数字照样 >0；③ `ms[i]` 不求值；④ **断终态而非状态转移**（先 `ensureClosed()` 再断它变 on）；⑤ **断「拼回原句」**（`indexOf` 必真 → 要断「mark 之前恰好 s 個字」且**数码位**）；⑥ Python `len(t)==len(list(t))` 恒成立 → 判非 BMP 只能 `ord(c)>0xFFFF`；⑦ **验了引擎没验接线**（抽出产品码自测 → 呼叫点漏传时照样全绿）→ 必须再配静态检查守呼叫点（判据：呼叫点数 ≥ 预期 **且** 实参个数够）。
  **每条集合/状态类断言都要问「样本为空、或前置已就位时，它是什么结果」**。
- ⚠️ **审查报告给的「建议改法」本身可能是错的**（P0-甲建议直接 `slice(s,e)`，照做新造 63 条错标）。**每条建议自己实测再动手。**
- **断言自己造的数据自己收走**（`finally`；清理函数**不能只收 dead 行**）。**断言红了 ≠ 数据错了**，先看它断的那批是什么。
- ⚠️ **注入脚本三个坑**：① **备份只在开头做一次**（`restore()` 里重备份会「越还原越坏」）→ 还原后**比对字节 + grep 锚点**；② **注入前先 assert 锚点存在**；③ **注入后要重跑 `export_static.py`** 再跑离线测试，并设 `BI_UI_TIMEOUT`，否则 `waitFor` 吃满 60s。
- ⚠️ **改数据形状必配断言**（给 `sents` 加字段有三处 `enumerate(sents)` 要同步，漏改 → `dist/` 留旧档**还能打开**）。⚠️ 批量改 pid 被 diff 计两次 → 先核对 `added` 桶。

## 离线快照 / 联机-离线一致性
- `dist/app.js` 是 `app/web/app.js` 的拷贝，靠「有没有 `window.BOOKINDEX_DATA`」切换。**永不复制第三份前端。**
- 导出 `app/tools/export_static.py`：⚠️ **`--check` / `--verify` 都是「只验不写」**（`main()` 直接 return）→ **真导出必须不带参数**。判断有没有同步：`diff <(tr -d '\r' < app/web/app.js) <(tr -d '\r' < dist/app.js)`（dist 是 CRLF，因 `export_static.py` 用默认 newline 在 Windows 下写）。
- ⚠️ **响应体组装必须放 db 层**（`index_payload` / `person_payload` / `place_payload`），端点与离线导出共用同一份。
- ⚠️ **`counts` 要给每块数据各记一份**（三块能各自独立坏掉而总数不变）。大 JSON 写 `JSON.parse('…')`（15MB 字面量撑爆 V8 AST）。
- ⚠️ 关系图快照 key 用 `"%g" % conf`；⚠️ `location.hash` 规范化「守卫与解析吃同一份」（`normHash`）。
- **凡是「按当前书作用域变化」的数字一律让前端算**（离线路由**忽略查询串**）。**常量漂移是同一类坏**（`ALIAS_KINDS` / `BOOKS[].era` / `ERA_NAMES` vs `pipeline/annotate.py` 的 `ERA_ORDER`）。
- ⚠️ **改了 UI 形状，旧断言会红**——那是断言过期不是 bug，把旧断言升级成新形状的判据，**别删**。
