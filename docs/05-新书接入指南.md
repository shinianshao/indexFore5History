# 新书接入指南 · 后汉书 / 三国志

> 面向下一步：把《后汉书》《三国志》接入现有「史记 + 汉书」双书管线。
> 本文不是设计文档（设计见 `docs/03`），而是**操作清单 + 踩坑复盘**——
> 每一条都来自接入《汉书》时的真实事故，照着做能省下重复踩坑的时间。

## 〇、接入全景（7 步）

一条新书从零到上线，顺序固定、不可乱跑（依赖关系与 `run_pipeline.py` 一致）：

```
① 注册书        books.json + fetch_book.py 的 BOOKS，先挂 ready:false
② 抓取           fetch_book.py --book <code>  → data/raw + volumes/<code>.json
③ 切分           build.py                      → data/corpus/<code>-*.json
④ 人物词典      build_dict.py                 → people.json（PERSONS + 篇主表）
⑤ 地名          build_places.py + annotate_places.py
⑥ 字面层守卫    check_trad.py（不过就中断）
⑦ 回归          verify.py --check + _ui_test* + _ui_sweep
```

前三步（①–③）可以并行做，产出独立；④ 依赖 ③；⑤ 依赖 ④（地名要挖掉人名区间）；
⑥ 必须最后跑。**每一步做完都先跑一遍 `run_pipeline.py`，确保既有书零回归再进下一步。**

## 一、分步清单与坑

### 第 1 步 · 注册书（半成品隔离阀）

- `data/dict/books.json` 加一条：`{code, name, order, volumes, source, ready:false}`。
- `pipeline/fetch_book.py` 的 `BOOKS` 加一条（`prefix` 用繁体，如 `後漢書/卷`）。
- **坑**：`ready` 标志是唯一一道"半成品隔离阀"。`books_sorted(ready_only=True)`
  只认 `ready:true` 的书——新书抓完、篇主表与人物词典补齐**之前**必须挂 `false`，
  否则半成品语料混进流水线会把史记/汉书的产物搅乱。汉书接入时靠这道闸隔离过。
- **坑**：`order` 决定前端「书」的排序与分书统计顺序，别和已有书撞号。

### 第 2 步 · 抓取（fetch_book.py）

汉书接入时踩过的坑，全部适用：

1. **卷号形态不规则**。不是 `卷001`～`卷130` 那么整齐，存在 `015b / 027下之上 /
   099中 / 100下` 这类 slug，且维基文库有**重定向**（实测汉书 131 个子页面里
   19 个是重定向）。**必须先解析重定向再抓**（`canonical_volumes()` 已做），
   否则同一卷抓多遍、正文重复进语料。
2. **非卷页要排除**。校語／叙例／別本转录是编者文字或重复转录，不入库。
   `canonical_volumes()` 的 `others` 列表就是干这个的。
3. **篇名抽取要简繁双匹配 + 按已知卷号精确剥**。正文繁体（「巻」是「卷」异写），
   篇名本身可能以数字开头（「十二諸侯年表」），不能 lstrip 数字集——
   正确做法是 `cn_number()` 先算出该卷号的中文数字再精确剥。
4. **抗限流**：请求间隔 2.5s、429/5xx 指数退避（15/30/60/90/120s）、
   全量跑完自动对失败卷补抓一轮、已有文件跳过（重复执行 = 补抓缺失）。

**后汉书/三国志 特定**：三国志正文之外有**裴松之注**，体量远超史记/汉书的三家注，
是抓取/切分阶段的头号新难题，务必先写探针（`--map-only` + 抽 1–2 卷看 HTML 结构）
再定剥离策略，别直接套用汉书的正则。

### 第 3 步 · 切分（build.py）

1. **三家注必须剥离**：维基文库把集解/索隱/正義夹注写在 `〈…〉` 内，不清掉的话
   一篇能从 5 千字膨胀到 3 万+（《天官書》实例），页面上显示的"原句"会变成注释。
2. **十表/八志是 `<table>`**：不能一刀切剔除表格，要按 class 区分——
   剔除 `ws-header`/`ws-footer`/`ws-noexport`（导航版权），保留
   `wikitable`/`dynlayout-exempt`（正文表），单元格按段抽取、要求含汉字。
3. **裴注（三国志）**：性质与三家注不同（是独立叙事而非夹注），剥离策略需单独设计。

### 第 4 步 · 人物词典（build_dict.py）——最容易出事的一步

1. **书作用域是"补人物"的正确姿势**（`PERSON_BOOKS_XX`，140 人先例）。
   不加 `books` 闸，新书补入的人物会去撞旧书里的**同名异人**：汉书接入时
   王成撞韩王成、王商从「楚穆王商臣」里被截出、建成侯撞彭越。
   **后汉书/三国志人名与史记汉书重叠更严重（曹操、刘备、孙权、诸葛亮全跨书），
   这道闸比汉书那次更重要。**
2. **别名归一是成败关键**。繁简 + 异体字 `VARIANTS` 收/不收有判据：
   - 收「书中只有一义」的（于/云/余/内/无/启/鼂/即…）；
   - **不收「两义都活」的**（后/里/干/钟/范/辟…），这类靠**词典补异写**而非字符归一。
   - 每收一对，都要跑「补完重跑完整管线 + 逐 id 比对人物层计数」的回归。
3. **篇主表（`CHAPTER_OWNERS_XX`）按纪传体例显式列出，不推断**——这是全书最大的
   人工工作量（汉书 108 篇），但换来可复核、零黑盒。
4. **繁体名必须过 `to_trad` 不动点**（`check_trad` 的 A/C 闸）。批量补人时
   曾被抓出 4 条：劉辟光→劉闢光、公子范→公子範、公孫閲→公孫閱、公子翚→公子翬。
   判据：繁名须满足 ① `to_trad(s)==s` ② `s==to_trad(t2s(s))`；正文写法不一致时
   一律降级为**显式别名**（别名不进显示层白名单，放非不动点形是安全的）。
5. **批量补人会吃掉单字地名**：人名占用区间判定若在「国+谥+爵」守卫**之前**，
   新补的「曹襄公」整串被人名盖住、守卫没机会跑。修法是区间放行前先判三段式
   （`s==match.start() and 3字 and 中字∈谥法 and 末字∈爵位`）。补人后必跑
   `_ui_test_places.js`。

### 第 5 步 · 地名

- 四道闸门（人名占用 → 裸匹禁用 → 姓名阻断表 → 邻字守卫）+ 单字「国+谥+爵」放行。
- **同名异地未做运行时消歧**（「梁」= 魏都大梁 vs 汉梁国）——后汉书/三国志会有
  大量同类（如「新城」「安陽」遍地都是），这是当前最大已知限制，接入前要心里有数。
- 单字县名风险高，别批量收，逐字评估守卫。

### 第 6 步 · 字面层守卫（check_trad.py）

- 七组断言（不动点/幂等/正名一致/元信息/短语陷阱/界面/正文元数据），失败即中断。
- 反向测试必须做：注入故障 → 必须命中 → 恢复 → exit 0。

### 第 7 步 · 回归

- `verify.py --check`：每条断言对应一个曾经踩过的坑，**改管线前先跑它**。
- **泛称验证必须分书**：`verify.py` 里史记 ≥75%、汉书 ≥60% 两条独立基线。
  新书接入后要**再加一条该书的基线**——先实测一个合理值再钉死，别照抄汉书 60%。
- `_ui_test*.js`（人物/地名/多书）+ `_ui_sweep.js`（全量逐条对账）+ `_ui_csscheck.js`。

## 二、后汉书 / 三国志 特定风险预判

> 以下是常识性预判，**接入前需实地核验**（先 `--map-only` 探针，再看 HTML 结构）。

| 风险 | 后汉书 | 三国志 |
|---|---|---|
| 卷数/结构 | 100 卷（本纪 10 + 列传 80 + 志 30） | 65 卷（魏书 30 + 蜀书 15 + 吴书 20） |
| 体例 | 断代史，与汉书几乎同源，**坑最可预测** | 纪传体 + 国别史混合，篇主归主逻辑要另议 |
| 注释 | 三家注规模，可复用现成剥离 | **裴松之注体量巨大**，头号新难题 |
| 志/表 | 志 30 卷是司马彪《续汉书》志合入，篇主/归属要标注清楚 | 无志书，但裴注混杂正文 |
| 人名重叠 | 与史记汉书大量重叠，书作用域要精细 | 与史记汉书重叠极重（曹操/刘备/孙权/诸葛亮…） |
| 地名同名 | 「新城」「安陽」等高频同名，同名异地问题放大 | 三国地名同名同样普遍 |

**建议接入顺序：先《后汉书》，后《三国志》。**
理由：后汉书体例与汉书同源，1–6 步的坑几乎全部可复用、阻力最小，先把流程再跑顺一遍；
三国志要额外解决裴注剥离这个全新难题，且篇主归主（国别史）逻辑需要单独设计，
放在流程成熟之后单独攻关。

## 三、接入完成的标准（验收门）

一条新书只有同时满足以下全部，才算"接入完成"，缺一不可：

1. `run_pipeline.py` 全链路绿（含 `check_trad` A–G 七道闸）。
2. 既有书逐 id **零回归**（人物 + 地名，`_snapshot_counts.py` 改前/改后对账）。
3. 新书命中合理：零命中地名 0 个、零命中人物 ≤ 个位数且可解释。
4. 泛称分书基线：为新书单独设一条，实测达标（不要照抄旧书数值）。
5. 全套前端测试绿：`_ui_test.js` / `_ui_test_places.js` / `_ui_test_books.js` /
   `_ui_sweep.js`（全量逐条 0 异常、0 运行期错误）。
6. 截图抽查：`_shot.js` 出几张新书页面截图，肉眼确认高亮、分色、称谓表无错位。

## 四、一句话记忆

接入新书 = **先挂 ready:false 隔离 → 解析重定向再抓 → 剥三家注/裴注 → 书作用域补人 →
篇主表显式列 → 繁体名过不动点闸 → 补人后跑地名回归 → 分书设泛称基线 → 逐 id 零回归**。
