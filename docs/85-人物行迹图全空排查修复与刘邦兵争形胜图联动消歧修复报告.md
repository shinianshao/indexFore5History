## 一、問題背景與用戶反饋根因分析

用戶在本地服務（`啟動服務.bat`，端口 8800）使用形勝輿圖模塊時反饋：
1. **「全部人的行跡圖都空了」**
2. **「劉邦的戰爭地圖鏈接到了曹操上，你好好再仔細檢查一遍吧」**

### 根因深度排查：

### 1. 「全部人的行跡圖都空了」之根因
- **通信斷層**：用戶透過 `啟動服務.bat` 運行 FastAPI 聯機服務時，頁面依賴 `/api/index` 端點返回的 `IDX` 數據對象。
- 服務端 `app/server/db.py` 的 `index_payload()` 原響應體中：
  ```python
  return {
      "book": book,
      "sort": sort,
      "persons": list_persons(book=book, sort=sort, counts=pc),
      "places": list_places(book=book, sort=sort, counts=lc),
      "chapters": list_chapters(book=book),
      "quick": quick_words(book=book),
      "strategicPlaces": STRATEGIC_PLACES,
      # 遺漏了 placeCoords 與 trajectories！
  }
  ```
- 同時，前端 `app.js` 原代碼僅靜態讀取 `(IDX && IDX.trajectories) || window.BOOKINDEX_DATA.trajectories`，未向服務端 `/api/person/{pid}/trajectories` 發起任何異步網絡請求。
- 在聯機無靜態 `data.js` 的環境下，`allTrjs` 始終為 `{}`，導致全部 61 人的生平行跡數組均為 `[]`，標籤欄顯示 `(0)`，地圖打點與事跡列表 100% 空白！

### 2. 「劉邦的戰爭地圖鏈接到了曹操上」之根因
- **狀態固化與盲目賦值**：
  1. `app.js` 中 `mapState.activeTrjPid` 默認寫死為 `"p_caocao"`；
  2. 在人物詳情頁 `renderPerson()` 中，跳轉按鈕原代碼為：
     ```html
     <button class="map-view-btn" data-act="view-itinerary" data-pname="劉邦" data-hubs="pl_pengcheng,...">
       在形勝輿圖上檢視行跡（涉足 18 處要塞） ➔
     </button>
     ```
     該按鈕**缺少 `data-pid` 屬性**，點擊處理函數中僅設置了 `mapState.itineraryPerson = "劉邦"` 與 `mapState.selectedHub = hubs[0]`，**既沒有切換到行跡模式，也沒有將 `mapState.activeTrjPid` 設為 `p_liubang`**！
  3. 當用戶切換到【歷代名賢 · 生平行跡】Tab 時，選中的始終是默認的曹操；
  4. 此外，在兵爭模式下，按鈕將 `mapState.selectedHub` 強制設為 `hubs[0]`（彭城），而彭城的考據卡片標題為《徐州腹心四戰重地 · 楚漢爭霸與曹操平徐州樞紐》，大篇幅展示曹操平徐州事跡，導致用戶產生「點劉邦卻鏈接到了曹操」的強烈混淆！

### 3. 「地點點擊無聚焦效果」之根因
- 前端 SVG 視界縮放全面採用 `mapState.curVb = {x, y, w, h}`；但原地點點擊回調中錯誤寫入了 `mapState.scale` 和 `mapState.panX/panY`，導致 viewBox 完全未變，地圖既不縮放也不居中。

## 二、架構修復與系統性治理方案

### 1. 聯機輕量級索引與前端 `TRJ_CACHE` 異步雙軌機制
- **服務端 `app/server/db.py`**：
  - 在 `index_payload()` 中補充輕量坐標庫 `placeCoords`（190 處，僅 32KB）與 `trajectoryCounts`（61 人記錄數字典，僅 1KB）；
  - 保證首屏與切換書目時網絡傳輸小於 35KB，避免傳輸 8.7MB 全量 JSON 拖慢服務。
- **前端 `app/web/app.js`**：
  - 構建 `TRJ_CACHE` 內存緩存字典；
  - 實現 `loadPersonTrajectories(pid, callback)` 異步獲取函數：
    - 離線版優先讀取 `window.BOOKINDEX_DATA.trajectories`；
    - 聯機版先查內存緩存，未命中時非同步請求 `/api/person/{pid}/trajectories`（SQLite 索引單次查詢僅 8ms），獲取後寫入 `TRJ_CACHE` 並即時渲染；
    - `loadIndex()` 首屏自動預加載當前激活人物足跡。

### 2. 人物詳情頁導航按鈕解耦與雙向聯動消歧
- 在人物詳情頁【主要行跡 · 兵爭與輿地交集】中，明確拆分為兩大專屬導航按鈕：
  1. 針對 61 位核心人物：
     ```html
     <button class="map-view-btn" data-act="view-trj-map" data-pid="p_liubang" data-pname="劉邦">
       📜 在生平行跡圖上檢視足跡 ➔
     </button>
     ```
     - 點擊後直接切換為 `mapState.mode = "trajectory"`；
     - 設置 `mapState.activeTrjPid = "p_liubang"` 並對齊典籍作用域；
     - 清除局部選中，還原全局視界並秒開劉邦 1,581 處行跡！
  2. 針對兵爭要塞涉足者：
     ```html
     <button class="map-view-btn" data-act="view-campaign-map" data-pid="p_liubang" data-pname="劉邦" data-hubs="...">
       ⚔️ 在兵爭形勝圖上檢視（涉足 18 處要塞） ➔
     </button>
     ```
     - 點擊後切換為 `mapState.mode = "campaign"`；
     - 設置 `mapState.itineraryPerson = "劉邦"` 並點亮 18 處要塞網絡；
     - 將 `mapState.selectedHub` 設為 `null`，不再盲目彈出「彭城 · 曹操」考據卡片；
     - 同步更新 `mapState.activeTrjPid = "p_liubang"`，確保用戶在頂部切換到行跡圖時依然精準保留在劉邦！
- **頂部雙 Tab 模式切換聯動**：
  - 在切換 `[⚔️ 兩漢三國 · 兵爭要地]` 與 `[📜 歷代名賢 · 生平行跡]` 時，自動雙向對齊 `itineraryPerson` 與 `activeTrjPid`，徹底杜絕人物跨模塊漂移。

### 3. 地點點擊視界計算與聚焦縮放修復
- 點擊地圖上的行跡點位或列表條目時：
  - 根據該地點經緯度計算畫布投影坐標 `pt = projectCoord(lng, lat)`；
  - 設置目標視界大小 `w = 450, h = 306`（約 2.2x 放大）；
  - 更新 `mapState.curVb = { x: pt[0] - w/2, y: pt[1] - h/2, w, h }`；
  - 地圖流暢放大並居中至該地點，周圍光環動態波紋聚焦；
  - 再次點擊或點擊【✕ 取消聚焦】按鈕時，自動平滑還原全景視界。
