## 一、问题背景与学术违和感根源

### 1. 现象
在旧版系统中，用户打开任意人物详情页（如**汉高祖刘邦、孔子、周公、商汤、秦始皇、项羽、汉武帝、汉光武帝刘秀**等），页面顶部都会横亘着一张大尺寸的：
> **《三國志》魏蜀吳分卷與裴松之注統計**  
> 《魏書》xx 處 · 《蜀書》xx 處 · 《吳書》xx 處

### 2. 根源剖析
原代码的渲染判断为：
```javascript
// 旧逻辑：只要在《三国志》或裴注中被提及的次数 > 0，即渲染该卡片
if (comb_tot_n > 0) return renderSgzBreakdownCard(...);
```
由于后世群臣上表进言经常**追述古人**（诸葛亮言必称“高祖、孝武”，魏蜀吴臣僚论政必引“周公、孔子、商汤、秦皇”），加之裴松之注大量援引前朝旧史，导致：
- 孔子在《三国志》被提到 63 处；
- 周公被提到 28 处，禹被提到 24 处，商汤被提到 24 处；
- 刘邦被提到 20 处，秦始皇被提到 4 处……
全库多达 **207 位先秦及两汉前代人物**被动“被赋予”了三国志分卷卡片，严重背离了人物所处的真实历史时代，造成强烈的视觉噪点与时代违和感。

## 三、双轨同构工程改造全貌

### 1. 后端接口治理（`app/server/db.py`）

```python
def sgz_breakdown(pid: str, pei_info: Optional[Dict[str, Any]] = None) -> Optional[Dict[str, Any]]:
    # 非三国人物直接返回 None，完全不向前端传输该字段
    if not is_three_kingdoms_person(pid):
        return None
    ...
```

### 2. 前端渲染双轨守卫（`app/web/app.js` & `dist/app.js`）
在离线计算 `computeSgzBreakdown(d)` 和人物详情渲染层加入双重拦截：
```javascript
function isThreeKingdomsPerson(p) {
  if (!p) return false;
  var dyn = p.dynasty || "";
  var era = p.eraRank != null ? p.eraRank : (p.era_rank != null ? p.era_rank : null);
  var pid = p.id || "";
  if (dyn === "三國" || era === 12) return true;
  if (HAN_MO_THREE_KINGDOMS_PIDS[pid]) return true;
  return false;
}

// 渲染层
var isSg = isThreeKingdomsPerson(p) || isThreeKingdomsPerson(d.profile || d);
var sgzBk = isSg ? (d.sgzBreakdown || computeSgzBreakdown(d)) : null;
if (sgzBk) {
  html += renderSgzBreakdownCard(sgzBk);
}
```
