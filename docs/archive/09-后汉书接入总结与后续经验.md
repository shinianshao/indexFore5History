**未完全达标 / 遗留（诚实记录）**：
1. **后汉书泛称占比 40%**（目标 60%）——剩余 guess 主要是**跨时代追述的合理兜底**
   （「昔武王伐殷」的武王、周成王等，era 远、保守判 guess），属**设计行为**而非误匹配；
   继续挖裸封号可再提，但收益递减。
2. **类传长尾**：儒林/文苑/方术等次要人物未全补（主传已补，附传用 `extract_persons` 滚动补）。

4. 单字县名 213 个未补、同名异地（梁）无运行时消歧——**既有已知限制**，非本次引入。

**总体：核心检索库可用、质量扎实；「泛称 60%」一条未达，但其缺口大半是合理的保守兜底。**

## 三、Token 评估

**估算（无精确计数器，基于会话规模推算）**：本次（含 R1–R5 + R2 收尾 + 双份日志/文档）
累计 **约 120–180 万 token**（输入+输出）。属**超长单会话**，中位数任务的 3–5 倍。

**构成分析（钱花在哪）**：
| 占比 | 消耗点 | 是否必要 |
|---|---|---|
| ~30% | **读大文件**（memory 578 行、SKILL 403 行、多份 references、build_dict 多次读） | 部分必要，**可用 grep 省一半** |
| ~25% | **代码生成**（400+ 人词条、探针脚本、文档） | 必要，但**脚本生成可省** |
| ~20% | **重复验证循环**（改→跑管线→查零命中→再改，多轮） | 部分必要，**可合并探针** |
| ~15% | **长报告/总结** | 必要 |
| ~10% | 试错（引号 bug、插入位置 bug、端口问题） | **可预先规避** |

**主要浪费点**：
1. 读了 `2026-09-21.md` 全文 578 行——其实只需 grep「待办/遗留/坑」关键词（省约 60%）。
2. 400+ 人词条多次逐行手写/读回——脚本生成+插入一次搞定（我后期改用了脚本，前期手写浪费）。
3. 每次改词典都重跑**完整管线**（含史汉 130+109 卷切分）——只改词典时可只跑 `annotate.py`。

## 四、三国志 / 晋书接入经验（保质前提下减少 token）

### 4.1 流程层：一次规划，分轮验收

1. **先写 5 轮规划再动手**（`docs/06`）——避免边做边想，每轮出口闸门明确，少走回头路。
2. **口径先问用户**（R1 先问「校勘/脚注怎么处理」）——一次对齐省掉「做错→返工」的 3–5 轮。
3. **每轮只跑必要验证**：改词典→只跑 `annotate.py`；改前端→只跑对应 `_ui_test`；
   全套 `run_pipeline` 留在**轮末**跑一次。少跑 50% 管线重跑。

### 4.2 技术层：复用资产，脚本生成

4. **直接复用 skill 资产**：`references/08`（方志补录）、`place_guards_template`、
   `check_trad_template`、`trad_template` 全部可直接套——三国志只需换词典，算法零改动。
5. **批量生成代替逐条**：人物/地名/篇主表用 `_gen_*.py` 脚本生成 + `_insert_*.py` 插入，
   一次写 100+ 条；**不要逐条手写再读回**（省 60% 生成 token）。
6. **探针固化进 skill**：本次写了 30+ 个一次性探针，下次三国志应先写**通用探针**
   （`_probe_corpus_stats`、`_probe_miss`、`_probe_generic_sub`），而不是每次重写。
7. **一次探针查多件事**：把「零命中 + 泛称构成 + 残留」合并进一个探针跑，少开 5 轮。

### 4.3 验证层：靠断言，不靠肉眼

8. **每修一个坑加一条断言**（`verify.py`），下次只跑 `verify` 不用重新人肉核（省大头）。
9. **唯一性/不动点校验前置**：地名字串四形态比对（x / s2t(x) / t2s / norm）写进筛选手册，
   避免 `build` 中断的 3 次返工。
10. **`ready:false` 贯穿全链路**（遍历语料的每个脚本都传 `ready_only=True`）——
    三国志接入时直接照做，别再踩半成品污染的坑。

### 4.4 读取层：最小化上下文

11. **大文件用 grep/read 定位**，不要全文读（578 行日志只需 grep 关键词；build_dict 只读表头）。
12. **子代理并行预研**（explore 读 skill/现有管线），主会话只拿结论——减少主上下文占用。

### 一句话心法

> **三国志/晋书接入 = 换词典 + 复用 5 轮骨架 + 脚本批量生成 + 断言守护 + grep 读取。**
> 算法/守卫/探针全部复用 skill，只重做「词典、篇主表、书作用域」三张表——
> 预期 token 可降到本次的 **40–50%**，质量持平或更高（守卫更全）。
