## 二、实施中出的问题

| 问题 | 后果 | 解决 |
|---|---|---|
| **导出时按拼音排序** | 打乱源码编排顺序，读回后 `people.json` 条目顺序变了、md5 不同 | 改回保持源顺序，拼音只作**只读辅助列**供人自己排序 |
| **`_apply_names.py` 不支持行尾注释** | 计划文件里写了 `# 证据` 后，整行被当成名字 | 改解析器跳过行尾注释 |
| **自己写的中文注释用了简体** | 触发字面层 F 界面闸失败（check_trad 扫全文，**注释也算**） | 界面与注释一律繁体 |
| **`_split_persons.py` 缺 `if __name__ == "__main__"`** | 跑起来安安静静退出 0、什么都没改，最难查 | 补上 |
| **为绕开「临时目录不可用」覆盖了 `TMP`** | Windows pip 不认 POSIX 路径，把 100 个垃圾文件写进项目根目录 | 不再覆盖 TMP，直接用系统临时目录装 |
| **端口 8770 被 VPN 客户端占用** | 回归一直卡在「服务未就绪」 | 默认端口改 8790，支持 `PORT=` 覆盖 |
| **打开了 `index.db` 的 WAL 没关** | 留下 `-wal` / `-shm` 残留 | 无功能影响，重建前先停服务即可 |

## 三、复查发现的新问题（含处置）

> 复查的结论是：**核心链路是真的通的，但它旁边长了四样东西。**

### 3.1 【已修·高危】导出脚本会覆盖权威源 —— 撞自己的红线 1

`build_workbook.py` 原本无条件 `wb.save(persons.xlsx)`。而 `persons.xlsx` 已经是权威源，
这意味着**你在表里改的别名、标的状态、写的备注，会被一次重跑悄悄冲回种子数据**。
违反了自己立的红线 1（「凡 pipeline 想写 Excel 的地方，一律改成写新版本 + 报差异」）。

补了闸门（`read_existing_rows` / `_human_row` / `resolve_target` / `_backup`）：

- 只比**人会写的列**（正名/朝代/头衔/简介/别名/状态/备注）；
- **完全一致** → 幂等重建，安静覆盖，一句话不多说；
- **检测到改动** → 原表一根手指不碰，改写 `<名>.new.xlsx` 并打印差异；
- `--force` 才覆盖，且先自动备份 `.bak-<时间戳>.xlsx`。

> ⚠️ **必须做值归一化**：Excel 空单元格读回来是 `None`，代码里是 `""`。
> 漏了这步实测 **1570 条全部被误判为「人改过」**——闸门过敏和没有闸门一样糟，
> 还多一层假警报。这是本轮调试最花时间的一处。

### 3.2 【已修】果然出现了重复副本

`app/tools/build_workbook.py` 是旧版复制：读 `people.json`（产物而非源数据）、
按拼音排序、输出另一个文件名，与真版差 93 行。
**危险的不是冗余本身，而是 DEV.md 的「常用命令」正指着它**——照着跑会拿到一个
看着正常、实则与权威源无关的产物。已删除（确认无任何代码引用）。

### 3.3 【已修】P0–P2 全部成果没进 git

最后提交停在 docs/19，而 `workbook/persons.xlsx` 是**不可再生的人工审定资产**。
已整理 `.gitignore` 后提交（`9450906`、`d710006`），工作区干净。

### 3.4 【已修】文档自身失真

DEV.md 写死的断言数、源码行数、耗时、guess 数全部过期；`.gitignore` 底部
「人工资产」注释还写着「build_dict.py 是 PERSONS 唯一来源」。
按「数字不进文档，只给取数命令」的铁律清掉了。

### 3.5 【未修·轻】`app/server/main.py` 用了废弃的 `@app.on_event("startup")`

只有 DeprecationWarning，不影响功能。改法是换成 lifespan 事件处理器。

## 七、新项目（`app/`）开发时，旧文件的影响评估

这是你特别要的一段。先说结论：**代码层零耦合，风险全在数据层和历史包袱上。**

实测 `app/` 下四个 Python 文件的 import，`pipeline` 一次都没出现——
新服务与旧管线之间**没有任何代码依赖**，只在 `people.json` / `book-data.json` 这两个
JSON 上交汇。做 P2 时把东西放进独立目录这一步，事后看是最对的决定。

### 7.1 有真实耦合的（动之前要看清）

| 旧文件 | 耦合方式 | 影响 |
|---|---|---|
| `data/dict/people.json` | `build_dict.py` 的唯一输出，也是 `build_index_db.py` 的输入 | 改了字典就要重跑整条链；**不能手改**（会被覆盖） |
| `data/index/book-data.json` | 静态版 `web/app-data.js` 与 `index.db` 的共同上游（32MB） | 静态版与新服务**同源**，所以两条链的命中数天然一致 |
| `web/index.html` + `web/app.js` | 与 `app/web/` 是**改写副本关系**（CSS 变量 12 vs 9，1787 vs 289 行） | **双写会漂移**。想统一视觉，正确做法是抽一份共享 CSS，不是每次两边同步改 |

> ⚠️ 最后这条是真正的隐患：两边各有一份 CSS 和各自的交互逻辑，
> 任何「统一视觉」的需求都会变成两次修改。你选的是「共用同一套 CSS 变量」，
> 但落地时只做到了**视觉一致**，没做到**代码共用**——这两件事差得很远。

### 7.2 无害但占用认知的（建议归档，不急着删）

| 项 | 规模 | 说明 |
|---|---|---|
| `docs/01`–`docs/20` | 约 28 份 | 历史推演。其中 `docs/21`（方案）、`docs/22`（上一轮总结）、本文档仍有参考价值；其余数字互相打架，别拿它们当事实源 |
| `pipeline/_probe_*.py` 等 | 34 个文件仍在根目录 | 多数已被 `query.py` 取代。判据：`_ai_*` / `_apply_*` / `_gen_*` 这套闭环工具**留在 pipeline**（会反复用）；`_probe_*` / `_fix_false_persons*` / `_split_persons` / `_snapshot_counts` 应迁 `_scratch/` |
| `shots/` | 33 张截图，11MB | UI 冒烟截图，已入 git。留着无害，也可整体移出 |

### 7.3 明确属于垃圾的（可清理，但**需你点头**）

| 项 | 规模 | 说明 |
|---|---|---|
| `data/index/book-data.json.bak` | 14.6MB | 废弃备份，未入 git |
| `web/app-data.js.bak`、`web/corpus-data.js.bak` | 约 20MB | 同上 |
| `.mimocode/` | 56MB（其中 node_modules 56MB） | **另一个 AI 编辑器留下的工作目录**，含 package.json / package-lock.json / skills/，部分文件已进 git。看着与本课题无关，但不清楚是否你有意保留 |

> 前两项删掉零风险。第三项因为不确定来源，**本轮没有动手**。

### 7.4 一句话评估

**旧文件不会阻碍新开发，但会干扰判断**：34 个一次性脚本与 28 份旧文档会让
「哪个才是当前事实」变得昂贵。真正的雷只有一个——`web/` 与 `app/web/` 的双写。
建议在 P3 之前，先把批量脚本归档，并在 `app/DEV.md` 顶部写一行
「事实源只有四处：`app/DEV.md` / `workbook/*.xlsx` / `pipeline/` 里的非 `_` 脚本 / `docs/21`–`23`」。

## 八、给新对话的交代（重要事项）

如果下一轮是全新会话，先看这一段，能省一小时。

### 8.1 五分钟上手

```bash
# 事实源
cat app/DEV.md                     # 唯一施工入口（三条红线 / 施工顺序 / 命令）

# 看东西
python app/server/main.py          # → http://127.0.0.1:8800/   日常查询
python app/tools/query.py --stats  # 库规模与 tier 分布

# 改字典（这是日常改动的唯一入口）
python pipeline/build_workbook.py  # 重导 Excel（有闸门，见 8.3）
<用 Excel 打开 workbook/persons.xlsx 手写>
python pipeline/build_dict.py      # 读表 → people.json

# ⚠️ 改完字典必须四步连跑，少跑任何一步都会丢账本（见 8.2 第 2 条）
python pipeline/annotate.py && python pipeline/annotate_pei.py \
  && python pipeline/annotate_js_note.py && python pipeline/annotate_places.py

# 重建索引库（全链路都是秒级，所以当初决定不做增量更新）
python app/tools/build_index_db.py

# 回归（约 90 秒）
bash scripts/run_all.sh            # 默认端口 8790（8770 被 VPN 占着）
```

### 8.2 六条不能破的规矩

1. **`pipeline` 永不回写 Excel**。想写 → 写新版本 + 报差异（已实现为闸门 + `--force`）。
2. **标注必须四步连跑**：`annotate.py` → `annotate_pei.py` → `annotate_js_note.py`
   → `annotate_places.py`。只跑第一步会丢裴注账本（句子 96,468 → 48,461，踩过一次）。
3. **句子 uid 是稳定主键**，不能随位置重算。
4. **别用 `python -c` 写复杂清洗脚本**：PowerShell 会吞引号/正则，写 `_*.py` 文件。
5. **界面文案与注释一律繁体**（check_trad F 闸扫全文）。
6. **断言只许升不许降**，每修一个坑就在 `verify.py` 加一条。

### 8.3 三个容易踩的坑

- **Python 解释器**：必须用系统 Python 3.12.10
  （`C:/Users/dell/AppData/Local/Programs/Python/Python312/python.exe`）。
  PATH 上第一位的托管版 3.13.12 **没装 opencc**，跑 `check_trad.py` 会假失败。
- **验证「可逆」不能用 openpyxl 改回去**：它会重写整个文件，字节不同，md5 回不到基准。
  必须**文件级 `cp` 备份/还原**。基准 md5：`ce7146606817b70d85d41ddf5875a618`。
- **`build_dict.py` 的 `ROOT` 是字符串**不是 Path，别写 `ROOT / "x"`，用 `os.path.join`。

### 8.4 下一次开口就该问的两件事

1. **P3 的快照 diff 要长什么样**：每次重建自动报「新增 / 消失 / 改归」三类变化，
   是打印到终端，还是沉淀成一张表或一个 diff 页面？这决定 P3 的落地形态。
2. **`web/` 静态版要不要抽共享 CSS**：现在新旧前端是双写，统一视觉之前
   得先决定「抽出来共用」还是「静态版冻结不再改」。
