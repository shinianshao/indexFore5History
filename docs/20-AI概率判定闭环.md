## 〇、一句话

守卫做不到 100% 正确。**让 AI 先判一遍并给出概率和依据，人只复核中低置信那堆**——
而不是让人从 279 条里逐条看起。

---

## 一、为什么这么设计（三条，缺一不可）

1. **AI 必须给依据，不只给标签**。
   「納婁敬」三个字就是「这是汉典」的依据，它同时能直接变成守卫规则；
   **只吐标签的判定无法沉淀**。所以判定表的「依据」列是**必填**，
   `_ai_judge.py` 会拒绝写入没有依据的判定。

2. **按置信度分三堆**：

   | 概率 | 处理 |
   |---|---|
   | ≥0.9 | **批量回填并写成规则**（`_apply_ai.py --apply`），人不看 |
   | 0.5–0.9 | 只给用户看这一堆（`docs/17-条目-AI复核.md`） |
   | <0.5 | 标 **未知**，不硬归——改 `none` 或保留 guess + UI「歸屬存疑」 |

3. **先让可计算的代理信号筛一遍**（共现率、按篇分布、书作用域、被更长名包含），
   AI 只看剩下的。这一层是 `_ai_autorule.py`。

---

## 二、五段链路（每段一个脚本，职责单一）

```
_gen_ai_batch.py   出条目：两项证据 + 可计算信号 + 空 ai 字段 → _ai_batch.json
        │
_ai_show.py        打印成人/AI 能批量读的紧凑文本（一条 4 行）
        │
_ai_judge.py       合并判定表（TAB 5–6 列）→ _ai_verdicts.json
_ai_autorule.py    「共现率 100%」机械项直接定掉（--dry 可预演）
        │
_gen_ai_batch.py   再跑一次：按 id 把判定合回批次（**数据重生成判定不丢**）
        │
_apply_ai.py       只落 prob≥0.9 那堆 → build_dict.py（--apply 真写）
        │
verify.py --check  每条结论钉成断言，基线只许升不许降
```

**判定为什么要单独存一份**：`_ai_batch.json` 每次重生成会整体覆盖，
判定写在里面会丢。判定按**条目 id** 存在 `_ai_verdicts.json`，
批次刷新时按 id 合回来。

### 条目长什么样

```json
{
  "id": "zi|p_x41509|叔夜",
  "kind": "zi",
  "q": "「叔夜」是不是嵇康（東晉）的表字？收进别名会不会误挂？",
  "surface": "叔夜",
  "person": {"pid": "p_x41509", "name": "嵇康", "dynasty": "東晉", "books": ["js"]},
  "signals": {"命中处数":3, "同句共现":2, "共现率":0.67,
              "本人字X句式":0, "他人字X句式":1, "被更长名包含":0,
              "书内命中":3, "书外命中":0, "分布书":{"js":3}, "分布篇数":3},
  "contexts": [...],
  "ai": {"action":"alias","prob":0.95,"target":"p_x41509","evidence":"…"}
}
```

### 判定表格式（`pipeline/_ai_judged/*.txt`，TAB 分隔）

```
<id>	<action>	<prob>	<target>	<依据>	[<繁体规范形>]
```

action ∈ `alias` / `reject` / `ctxrule` / `bookcand` / `default` / `drop` / `keep` / `unknown`。
第 6 列只在语料是简体形时才填（**别名铁律：只写繁体**，如「季产」→`季產`）。

## 三、判表字时的三条经验（下一轮直接照抄）

1. **`books` 决定误挂能不能发生**。限书的人只在指定书内匹配
   （`annotate.py` 书作用域），书外的同形串根本吃不到。
   所以判「收不收」只看 **书内命中** 里有没有错的，书外的不用管。
   ——这一条把 236 条里的绝大多数直接判死。

2. **`本人字X句式`＝「全名＋字＋表字」整串出现**，是传主铁证；
   `他人字X句式` 高往往是**同字他人**（王莽字巨君 / 郑弘字巨君），必拒。
   光看「字」字相邻会误判——`字X句式` 里两类要分开计。

3. **四类典型误抽**（抽查 14 条里 9 条中招，依旧是主力）：
   跨词边界（博士**弟子治**、遭**世康**平、名曰**靈秀**山）、
   被更长名包含（申**叔時**）、同字他人（**叔平**是敞/參的字）、
   亲属称谓（**伯祖**、**元孫**）。
   另有第五类本轮新见：**爵位/篇名**（「立皇**子瑋**」＝皇＋子瑋、
   「《**文王**世子》」＝禮記篇名）。

## 四、本轮结论（数字以 `--stats` 当次输出为准）

| 类别 | 判定 | 落地 |
|---|---|---|
| 表字 | alias | 补进 `PERSONS` 别名（繁体＋OpenCC 简体） |
| 表字 | reject | 不动（同字他人 / 跨词边界 / 亲属称谓） |
| 泛称 | **drop** | 「關內侯」是二十等爵的第十九级，**不是人名** → 从 `GENERIC_MANUAL`、`GENERIC_DEFAULT` 与蕭望之别名里摘掉，整串出索引 |
| 泛称 | bookcand | 漢書/後漢書裸「文王」→周文王（era 档被西汉劉禮拉偏，61/70、23/28 处错）；三國志裸「武王」→曹操（候选里**根本没有曹操**） |
| 泛称 | ctxrule | 《文王世子》是篇名 → `window/世子 → None` |
| 泛称 | keep | 抽查无误挂，不动 |
| 泛称 | unknown | 进人工复核清单，**依据里写明缺哪个候选人** |

### ⚠ 本轮踩到的两个坑（都加了防复发措施）

1. **`GENERIC_MANUAL` 有重复键**：`文王` / `武王` / `景帝` 各写过两份。
   Python 字面量**后写者静默覆盖先写者**——脚本往第一份里加了 `p_caocao`，
   生效的却是下面那份，**改了等于没改**。
   → 已在 `build_dict.py` 加 `_assert_no_dup_dict_keys()`（AST 层查重，
   对 `GENERIC_MANUAL` / `GENERIC_BOOK_CANDIDATES` / `GENERIC_DEFAULT` /
   `GENERIC_CONTEXT_RULES` 四个表生效）。

2. **`_gen_ai_batch.py` 里 guess 计数忘了自增**：泛称条目一度全部显示
   `guess处=0`，而 tier 构成里明明有 guess 131。看信号与分布打架时先怀疑脚本。
