### 2026-10-03 凌晨（HY4）补的两项

**⑤ 完整称谓表**：数据在 annotate 阶段就由 `build_alias_list` 算好了（**3,926 条**，
含类别 / 次数 / 按书分账），过去只进 book-data.json，库里没有 → 人物页只能显示扁平别名，
看不出「漢王 ×739」和「劉邦 未用」的差别。现在建表 `person_aliases` 原样灌入。

⚠️ **一个刻意的设计选择**：按书收窄放在**前端**（`aliasScopeN` 用 `byBook` 算），
不给 `db.person_alias_list` 加 `book` 参数——离线版没有服务端，请求里带 book 只会被
离线路由 `person/([^/?]+)` 当查询串忽略，理应收窄时收不到等值结果，两边就悄悄不一致了。
前提是 `n == ΣbyBook`（已验证对全部 3926 行成立，verify_p3 [14] 守着）。

**⑥ 「前朝」标记**：完整版（索引拆成两组）在 docs/29 §五 已被否掉，降级成条目上加「前朝」。
`persons.era_rank` / `books.era_from-to` 进库；**史记是通史没有区间、169 人缺 eraRank，
一律不标、不猜**。判断同样放前端（`isFormerEra`），理由同上。

**⑦ 网页「标错」入口（P3-4）**：`overrides` 这条纠错链过去只有命令行
（`overrides.py add --uid … --nth N`），而 nth 只能靠 `show` 手数——等于没入口。
现在人物页每条命中 hover 出「標錯」，就地展开一行面板：输人名 → 点候选 → 写进
`workbook/overrides.xlsx`（UI 代写，pipeline 侧依然只读，红线 1），另有「不是他」= drop；
已标错的命中带「已標錯 → 項羽」徽章 + 撤銷；顶部提示「已記錄 N 條糾錯，重建後生效」。

⚠️ **nth 必须由后端算**（`db.mention_nth`）：前端看到的是「这个人在本句里第几条」，
而 nth 是「本句**所有人**命中里第几条」。实测样本：某句里「漢王」是全句第 3 条命中，
但在劉邦自己的命中里排第 2——前端算就会改到别人头上，**而且不报错**
（`overrides.apply` 只按 nth 取第几条，取错也照样报「改歸 1 條」）。

⚠️ **UI 测试写权威源的问题**：revoke 是**改状态不删行**，UI 测试真点一次「标错」就会
给 `workbook/overrides.xlsx` 留两行 dead 行，每次回归多两行、永远脏着（现有
`purge_test_rows` 只认带自检标记的行，UI 点击不会带标记）。
解法是新增 **`BOOKINDEX_OVERRIDES`** 环境变量（与 `BOOKINDEX_DB` 同一套约定）：
`run_all.sh` 给临时服务指向 `data/index/overrides.ui-test.xlsx`（已 gitignore），
权威源一根手指都不碰；服务启动时会把「写入的不是权威源」嚷出来，
`verify_p3` [16] 也断「默认落点 == workbook/overrides.xlsx」。

### 关键结论：两处「悲观估计」被实测推翻

   全部可自动生成，**不需人工**；且只有 **1 个**被 relations 引用。
   docs/29 估的「4h + 4h 且同名必须人工」→ 实际约 2h。
2. **裴注比预想丰富**：`pei-data.json` 实有 **523 人 / 65 篇 / 4,173 条命中**（docs/29 记 451/2,829），
   而且**带 items 明细**（含 `cid`/`pseq`），能直接跳原文。

## 五、这一轮踩的坑（都已写进 MEMORY.md，这里只列标题）

- **「按 pid 索引的表」不止 relations.xlsx**：`check_trad.py` 的 `TRADNAME_EXCEPTIONS`
  也是按 pid 作键 → 改 pid 必须同步，否则 C 闸红 18 条。
- **xlsx 的 sheet 名 / 列名一律自动探测**：`persons.xlsx` 的表叫中文 `人物`；
  `persons` 表没有 `era` 列（是 `dynasty`）；`mentions` 没有 `book` 列；
  `persons` 主键是 `id` 不是 `pid`。同一坑已踩 5 次。
- **改数据形状必须配断言**：给离线快照的 `sents` 加段号（第 4 位）时，
  `export_static.py` 里有**三处** `enumerate(sents)` 要同步，漏了两处 →
  导出中途炸，`dist/` 留着上一次的旧档（**还能打开**，最难发现）。
- **快照 diff 盲区**：批量改 pid 会被同时计进 `added` 与 `pid_changed`
  （实测报「新增 306」，全是改名，真正新增 0）。做批量 pid 改动前先核对 `added` 桶。
- **UI 测试写错时症状是「等不到」不是报错**：原文层在 `#readerBody` 不在 `#out`；
  人物索引条目是 `.item[data-name]` 而 `.row[data-pid]` 是搜索结果行；
  **检索靠点按钮触发**（`qEl` 只绑 keydown，没有 input）。
- **红线断言要断在「会被打破的那一层」**：注文不进 mentionCount 这条，
  断在库里查不出来（破法是有人往 `person_payload` 里拼），
  第一版就栽在这 → 改成逐条查 payload 里的注文标记。
