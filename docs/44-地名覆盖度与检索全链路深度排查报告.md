### 根因二：别名/异体映射断层与单字压制副作用

1. **城邑复合词无映射**：
   - 库里收录了单字“宛”（南阳宛县），打标了 447 处；但用户搜“宛城”，由于没有登记“宛城”别名，**返回 0 条**！
   - 库里收录了“許昌”，但在汉魏禅代前常称“许都”，未登记别名；用户搜“许都”，**返回 0 条**！
   - 库里收录了“建康”，别名有“建業/建业”，但古籍中常见的“建鄴/建邺”未收录；用户搜“建邺”，**返回 0 条**！
   - 库里收录了单字“譙”，但未登记“谯县/谯城”。
2. **单字压制规则导致的漏标**：
   - 在 `pipeline/build_places.py` 中，为防止人名和动词误标，设置了 `BARE_OFF = set("許代隨息舒黃徐漢濟塞相苦蒙樊亳六棠英潛紀申")`。
   - 这本意是合理的（如“樊”防止与“樊哙”撞车），但由于**没有同步补充“樊城”这一多字实体**，导致五史中所有“关羽围樊城”、“曹仁守樊城”等 22 处重要记载在系统中彻底失标！

### 根因三：工程架构上的管线与权威源割裂

在排查工程链路时，发现了极其关键的技术债：
1. **`build_dict.py` 根本不读 `workbook/places.xlsx`**：
   - `rebuild.py` 第 62 行注释宣称：“讀 workbook/*.xlsx → people.json / places.json”；
   - 但实际上 `build_dict.py` 内部**只有读取 `persons.xlsx` 的代码，完全没有处理地名的逻辑**！
2. **地名数据依然硬编码在 `pipeline/build_places.py` 中**：
   - `data/dict/places.json` 的真正来源是 `build_places.py` 里的 Python 列表 `PLACES = [...]`；
   - 而 `workbook/places.xlsx` 只是由 `build_workbook.py` 从 `places.json` 反向导出的只读视图！
   - **后果**：即使在 Excel 中修改或新增地名，执行 `rebuild.py` 也会被完全无视。这直接切断了人工维护和扩充地名库的正常途径！

---

### 根因四：前端搜索交互提示盲区

1. **输入框下拉建议（Datalist）局限**：
   - 前端输入框 `fillDatalist()` 预填的全部是当前库里的 1,575 处地名；
   - 用户在输入框打字时，输入“荆”、“赤”、“官”、“武”、“潼”，下拉框没有任何联想提示，直接强化了“系统里根本查不到”的体验。

## 三、治理与升级方案（建议路线图）

要彻底根治“地名不全、欠缺很多”的现状，建议分三步实施：

### 阶段一：打通数据流契约（P0 基础工程）
1. **让 `workbook/places.xlsx` 成为真正的唯一权威源**：
   - 改造 `pipeline/build_dict.py`（或在 `pipeline/` 中规范化），增加 `_load_places()`，优先从 `workbook/places.xlsx` 的“地名”Sheet 读取；
   - 确保 `rebuild.py` 一键重建能直接消费 Excel 中维护的地名；
   - 彻底将 `PLACES` 静态硬编码解耦为种子回退。

### 阶段二：系统性扩充五史核心地理库（约 300~500 处高频实体）
1. **新增“州”类型**：
   - 补充汉魏十三州：荆州、扬州、益州、兖州、冀州、青州、幽州、并州、凉州、交州、豫州、徐州、司隶（及雍州、梁州、广州等）；
   - 在前端 `PLACE_KIND_ORDER` 中加入“州”，置于国、郡之间。
2. **补齐三国两晋名城重镇与军塞**：
   - 武昌、夏口、京口、姑孰、新野、小沛、柴桑、金墉城等。
3. **补齐战役古战场与名隘**：
   - 赤壁、官渡、街亭、祁山、五丈原、樊城、延津、乌巢、定军山、濡须口、麦城、白帝城；
   - 潼关、阳平关、剑阁、散关、居庸关、玉门关、阳关等。
4. **建立城邑别名长名规则库**：
   - 为常用单字城邑补充长名别名：“宛”→“宛城”；“许昌”→“许都”；“建康”→“建邺/建鄴”；“洛阳”→“洛阳城/雒阳”。

### 阶段三：打标精度与单字防误伤验证
- 严格遵循 `annotate_places.py` 的设计原则：
  - 新增的多字地名（赤壁、官渡、街亭、武昌、潼关、荆州）本身字串特征极其明确，具备高置信度（tier="core"），直接全局匹配，无需复杂守卫，也不会造成误标；
  - 跑通 `verify_p3_place.py` 与全系统断言，确保 100% 绿色回归。
